ML & AI Engineering Curriculum

One track · 13 courses and a thesis · 108 weeks at 10–12 hours a week · Updated November 16, 2026

Program overview

This is one track: 13 courses over 108 weeks (about 25 months) at 10–12 hours a week, ending in a thesis. It merges the earlier two-track roadmap with the Self-Taught MS in ML, Deep Learning & LLMs plan. You get the master's-level depth (generative models, reasoning and RL, Stanford lectures, a thesis) and the practical engineering (weekly schedules, checkpoint tests, RAG, agents, evals, MLOps).

The order is deliberate. After the foundations, Term 2 teaches you to build LLM products, so you're employable as an AI engineer about 9 months in. Terms 3–5 then take you to model-building depth.

How each course works

  1. Summary — what the course is for
  2. Learning outcomes — what you can do when you finish
  3. Focus on — where to spend extra effort, and what to skip
  4. Resources — main text (read fully), lectures to watch alongside, and supporting material, all linked
  5. Weekly schedule — topic, reading and practice for each week
  6. Checkpoint test — every item must pass before you move on

Weekly study rhythm

Session Time What you do
Weekday × 3 1.5–2 h each Read one chapter, take notes in your own words, do the exercises
Weekend block 4–5 h Watch the matching lecture, code the chapter, push to GitHub
Sunday review 30 min Explain the week's concept aloud or in a short post (Feynman test)

Grading yourself: a course passes only when (1) every checkpoint test item is done, (2) its projects are on GitHub with a README, (3) you can explain the core ideas without notes, and (4) you've written a short public post about one thing you learned. A course you can't pass this way gets repeated, not skipped. If time gets tight, compress Terms 4–5, but never skip ML 501's math.

Term 1 — Foundations (Weeks 1–24)

Term goal: by week 24 you can derive gradient descent by hand and ship an end-to-end classical ML project.

ML 500 — Python for data (Weeks 1–2)

Summary: You already know Python, so this short course covers only the scientific stack: NumPy, pandas and plotting. Every later course assumes you can manipulate data quickly.

Learning outcomes — by the end you can:

  • Vectorize computations with NumPy arrays and broadcasting instead of loops
  • Load, clean, reshape, group and join data with pandas
  • Plot distributions and relationships with matplotlib
  • Work comfortably in Jupyter, and manage environments with venv or uv

Focus on: vectorized thinking and pandas groupby/merge. Skip anything that re-teaches basic Python syntax.

ML 501 — Math for ML (Weeks 3–12)

Summary: Build working intuition for the math every ML method runs on: linear algebra, calculus, probability and optimization. The goal is to read the notation and use it in code, not to write proofs. This is what separates people who use models from people who understand them; your BSCS background lets you go faster where it's review.

Learning outcomes — by the end you can:

  • Treat a matrix as a transformation, and explain rank, inverses, eigenvectors, SVD and PCA
  • Take gradients and apply the chain rule through nested functions
  • Explain gradient descent and basic constrained optimization
  • Work with common distributions, expectation, variance and Bayes' theorem
  • Explain maximum likelihood estimation, confidence intervals and hypothesis tests

Focus on: the geometric picture of matrices, the chain rule and optimization. Backpropagation (DL 701) is the chain rule applied many times. Skip formal proofs.

ML 502 — Statistical and classical ML (Weeks 13–24)

Summary: Learn the standard ML workflow and the core algorithms that still dominate tabular data in industry. Most real-world ML mistakes happen in evaluation, so this course spends as much time on validation as on models.

Learning outcomes — by the end you can:

  • Run an end-to-end ML project: framing, exploration, feature engineering, training, evaluation
  • Explain and apply linear and logistic regression, k-NN, decision trees, random forests, gradient boosting and SVMs
  • Use unsupervised methods: k-means clustering and PCA
  • Choose the right metric (RMSE, precision, recall, F1, ROC-AUC) and validate with cross-validation
  • Diagnose overfitting with the bias–variance tradeoff, and fix it with regularization
  • Spot and prevent data leakage

Focus on: evaluation, leakage and gradient boosting (XGBoost or LightGBM), which wins most tabular problems. Use scikit-learn Pipeline for everything.

Term 2 — Building with LLMs (Weeks 25–40)

Term goal: by week 40 you have shipped an LLM product with RAG, tools and an eval suite, and you're employable as an AI engineer. The main text for the whole term is AI Engineering by Chip Huyen, with its companion repo. Build in Go where you can, and use Python only where the tooling demands it.

AIE 601 — LLM foundations and APIs (Weeks 25–27)

Summary: Get a working mental model of how LLMs behave, then learn to call them well from code: structured output, tool calling, streaming, and managing cost and latency.

Learning outcomes — by the end you can:

  • Explain tokens, context windows, temperature, embeddings and why models hallucinate
  • Call the Claude and OpenAI APIs from Go and Python, with streaming
  • Get reliable structured JSON output and use tool (function) calling
  • Use prompt caching and batching, and estimate the cost and latency of a feature

Focus on: tool calling and structured output, which every later course builds on. Use the raw SDKs rather than frameworks, so you see what's happening.

AIE 602 — Prompting and RAG (Weeks 28–32)

Summary: Learn to control model behavior with prompts and context, then ground answers in your own data with retrieval-augmented generation (RAG), the most common pattern in production LLM apps.

Learning outcomes — by the end you can:

  • Write clear system prompts, use few-shot examples, and structure prompts with XML or JSON sections
  • Decide what goes into the context window and in what order (context engineering)
  • Chunk documents, generate embeddings and store them in a vector database
  • Build hybrid search (keyword plus vector) and add a reranker
  • Measure retrieval quality separately from answer quality

Focus on: retrieval quality. Most bad RAG answers come from bad retrieval, not bad prompts. Use databases you already run: pgvector in Postgres, or Valkey's vector search.

AIE 603 — Agents and MCP (Weeks 33–36)

Summary: Build systems where the model decides which tools to call and in what order. Learn the standard workflow patterns first, and when a full agent is actually needed.

Learning outcomes — by the end you can:

  • Tell workflows (fixed steps) from agents (model-chosen steps), and pick the simpler one when it works
  • Implement prompt chaining, routing, parallelization and orchestrator–worker patterns
  • Write an agent loop from scratch: call the model, run tools, feed results back, stop safely
  • Design tools an LLM can use well: clear names, descriptions, inputs and error messages
  • Build and connect an MCP server, so your tools work across AI apps

Focus on: writing the agent loop yourself before touching any framework, and tool design. Go is a first-class MCP language, so build your servers in Go.

AIE 604 — Evals and production (Weeks 37–40)

Summary: Learn to measure whether an LLM feature actually works, and to run it safely and cheaply in production. Systematic evals separate professional AI engineers from hobbyists.

Learning outcomes — by the end you can:

  • Build an eval set from real examples, and score outputs with code checks, human labels and LLM-as-judge
  • Run evals as regression tests in CI whenever a prompt or model changes
  • Add tracing and observability to every model call
  • Defend against prompt injection and data leakage, and add guardrails
  • Handle rate limits, retries, fallbacks between models, and caching
  • Run open models locally and compare them with hosted APIs on cost and quality

Focus on: evals. Start every feature by writing 20–50 test cases, before you write the prompt.

Term 3 — Deep learning (Weeks 41–64)

Term goal: by week 64 you can implement a transformer from a blank file, train it on a GPU, and train a small generative model.

DL 701 — Neural networks and deep learning (Weeks 41–56)

Summary: Understand how neural networks learn, and train them confidently in PyTorch. You'll build the core machinery from scratch once, so frameworks stop being magic, then use PyTorch properly.

Learning outcomes — by the end you can:

  • Explain activations, loss functions and backpropagation, and implement autograd from scratch
  • Write a full PyTorch training loop: tensors, autograd, Dataset/DataLoader, GPU use, checkpointing
  • Choose and tune optimizers (SGD, momentum, Adam) and learning-rate schedules
  • Apply initialization, normalization, dropout, weight decay and data augmentation
  • Build CNNs and residual networks, and use transfer learning
  • Explain RNNs, attention and the transformer, and implement self-attention
  • Debug training: loss curves, overfitting a single batch, exploding or vanishing gradients

Focus on: writing the training loop by hand and debugging it. Karpathy's series is the highest-value resource in this curriculum; do every exercise.

DL 702 — Generative models (Weeks 57–64)

Summary: Go beyond classifiers to models that generate data: VAEs, GANs, normalizing flows and diffusion. This course also covers self-supervised learning and scaling laws, the ideas behind modern foundation models.

Learning outcomes — by the end you can:

  • Explain self-supervised and contrastive learning, and how embeddings are learned
  • Derive the evidence lower bound (ELBO) and train a VAE
  • Explain GANs, normalizing flows and diffusion, and their trade-offs
  • Train a small diffusion model from scratch
  • Explain scaling laws and what they predict about model size, data and compute
  • Read a classic paper and reproduce one of its results at small scale

Focus on: diffusion and the ELBO. They're the mathematically hardest ideas here, and they recur in modern models. Treat GANs and flows as lighter survey topics.

Term 4 — LLMs and reasoning (Weeks 65–88)

Term goal: by week 88 you have pretrained a small GPT, fine-tuned an open model, and improved a model's reasoning with reinforcement learning.

LLM 801 — LLMs from scratch (Weeks 65–76)

Summary: Learn how large language models are built and pretrained by building one yourself, from tokenizer to training loop to fine-tuning. Type every line of code; don't copy it.

Learning outcomes — by the end you can:

  • Explain and implement tokenization (BPE), embeddings and positional encoding
  • Implement causal multi-head attention and a full decoder-only GPT
  • Pretrain with next-token prediction, and load pretrained GPT-2 weights
  • Explain sampling (temperature, top-k, top-p) and the KV cache
  • Fine-tune for classification and instruction following
  • Make training efficient on one GPU: mixed precision, gradient accumulation, checkpointing

Focus on: Raschka's book end to end, then the \~100M-parameter pretraining project. Rent a cloud GPU for the project weeks rather than buying hardware.

LLM 802 — Fine-tuning, alignment and reasoning (Weeks 77–88)

Summary: Adapt real open models to your tasks and improve how they reason. The course starts with just enough reinforcement learning theory to understand RLHF and GRPO, then moves to parameter-efficient fine-tuning, preference tuning and reasoning methods.

Learning outcomes — by the end you can:

  • Explain MDPs, value functions, temporal-difference learning and policy gradients
  • Fine-tune open models with LoRA and QLoRA on a single GPU, and build instruction datasets
  • Apply preference tuning (DPO) and explain RLHF
  • Use inference-time scaling (sampling, self-consistency, verification) to improve reasoning
  • Apply RL with verifiable rewards (GRPO) and distillation to a small model
  • Evaluate a model fairly before and after every change

Focus on: the two projects. The RL weeks are there so GRPO and RLHF make sense; don't go deeper into classic RL than the listed chapters.

SYS 901 — ML systems and MLOps (Weeks 89–96)

Summary: Take models from notebook to reliable service. Your backend, Go and Docker experience is an advantage here, since many ML engineers struggle with exactly this part.

Learning outcomes — by the end you can:

  • Design an ML system around business goals, with reliability, scalability and maintainability in mind
  • Build reproducible training: data versioning, feature pipelines, experiment tracking, a model registry
  • Avoid training–serving skew, and serve models as batch jobs or online APIs, including LLMs with vLLM
  • Monitor for data drift and model degradation, and trigger retraining
  • Set up CI/CD for ML code, data and models
  • Answer an ML system design interview question in 45 minutes

Focus on: reproducibility and monitoring, which are new to you. Move faster through serving and containers.
